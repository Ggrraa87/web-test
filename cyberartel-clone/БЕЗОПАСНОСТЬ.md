## 🐳 DOCKER БЕЗОПАСНОСТЬ

### 1. Запуск от непривилегированного пользователя

**Проблема:** Контейнер запускается от root.

**Решение:** Создайте пользователя внутри контейнера.

Обновите `Dockerfile`:
```dockerfile
FROM nginx:alpine

# Создаём непривилегированного пользователя
RUN addgroup -g 1001 -S appuser && \
    adduser -u 1001 -S appuser -G appuser

# Удаляем стандартную конфигурацию nginx
RUN rm /etc/nginx/conf.d/default.conf

# Копируем конфигурацию
COPY nginx.conf /etc/nginx/conf.d/

# Копируем файлы сайта
COPY html/ /usr/share/nginx/html/
COPY css/ /usr/share/nginx/html/css/
COPY js/ /usr/share/nginx/html/js/
COPY images/ /usr/share/nginx/html/images/

# Меняем владельца файлов
RUN chown -R appuser:appuser /usr/share/nginx/html && \
    chown -R appuser:appuser /var/cache/nginx && \
    chown -R appuser:appuser /var/log/nginx && \
    chown -R appuser:appuser /etc/nginx/conf.d && \
    touch /var/run/nginx.pid && \
    chown -R appuser:appuser /var/run/nginx.pid

# Переключаемся на непривилегированного пользователя
USER appuser

EXPOSE 8080

CMD ["nginx", "-g", "daemon off;"]
```

### 2. Ограничение ресурсов

Обновите `docker-compose.yml`:
```yaml
version: '3.8'

services:
  web:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: itsales-website
    ports:
      - "8080:80"
    restart: unless-stopped

    # Ограничение ресурсов
    deploy:
      resources:
        limits:
          cpus: '0.5'        # Максимум 50% CPU
          memory: 512M       # Максимум 512MB RAM
        reservations:
          cpus: '0.25'       # Резерв 25% CPU
          memory: 256M       # Резерв 256MB RAM

    # Безопасность
    security_opt:
      - no-new-privileges:true  # Запрет повышения привилегий

    # Read-only файловая система (кроме необходимых папок)
    read_only: true
    tmpfs:
      - /tmp
      - /var/run
      - /var/cache/nginx

    networks:
      - itsales-network

networks:
  itsales-network:
    driver: bridge
```

## 🌐 NGINX БЕЗОПАСНОСТЬ

### Улучшенная конфигурация nginx.conf

Замените содержимое `nginx.conf`:

```nginx
server {
    listen 80;
    server_name localhost;

    root /usr/share/nginx/html;
    index index.html;

    # Скрываем версию Nginx
    server_tokens off;

    # Gzip сжатие
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript application/x-javascript application/xml+rss application/json;

    # Основная локация
    location / {
        try_files $uri $uri/ /index.html;

        # Ограничение размера запроса
        client_max_body_size 10M;
    }

    # Кеширование статических файлов
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }

    # Запрет доступа к скрытым файлам
    location ~ /\. {
        deny all;
        access_log off;
        log_not_found off;
    }

    # Запрет доступа к служебным файлам
    location ~ /\.git {
        deny all;
    }

    # БЕЗОПАСНОСТЬ: Заголовки защиты

    # Защита от кликджекинга
    add_header X-Frame-Options "SAMEORIGIN" always;

    # Защита от MIME-sniffing
    add_header X-Content-Type-Options "nosniff" always;

    # XSS защита
    add_header X-XSS-Protection "1; mode=block" always;

    # Referrer Policy
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Content Security Policy (CSP)
    add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self';" always;

    # Permissions Policy (ранее Feature Policy)
    add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;

    # HSTS (только для HTTPS, закомментировано для HTTP)
    # add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

    # Ограничение методов HTTP
    if ($request_method !~ ^(GET|HEAD|POST)$ ) {
        return 405;
    }

    # Ограничение rate limiting (защита от DDoS)
    limit_req_zone $binary_remote_addr zone=limitzone:10m rate=10r/s;
    limit_req zone=limitzone burst=20 nodelay;

    # Логи
    access_log /var/log/nginx/access.log;
    error_log /var/log/nginx/error.log warn;
}

# Rate limiting зона (добавить в http блок)
# limit_req_zone $binary_remote_addr zone=limitzone:10m rate=10r/s;
```

**Примечание:** Для применения `limit_req_zone` нужно создать отдельный файл `nginx-main.conf`.

## 🔐 SSL/HTTPS НАСТРОЙКА

### Вариант 1: Let's Encrypt (бесплатно)

#### Шаг 1: Установите Certbot

```bash
sudo apt update
sudo apt install certbot python3-certbot-nginx
```

#### Шаг 2: Получите сертификат

```bash
# Замените yourdomain.com на ваш домен
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com
```

#### Шаг 3: Обновите nginx.conf для HTTPS

```nginx
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;

    # Редирект на HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name yourdomain.com www.yourdomain.com;

    # SSL сертификаты
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;

    # SSL настройки (рекомендации Mozilla)
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384';
    ssl_prefer_server_ciphers off;

    # OCSP Stapling
    ssl_stapling on;
    ssl_stapling_verify on;
    ssl_trusted_certificate /etc/letsencrypt/live/yourdomain.com/chain.pem;

    # HSTS
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;

    # Остальная конфигурация...
    root /usr/share/nginx/html;
    index index.html;

    # ... (все остальные настройки из nginx.conf)
}
```

#### Шаг 4: Автоматическое обновление

```bash
# Проверка автообновления
sudo certbot renew --dry-run

# Сертификаты будут обновляться автоматически
```

### Вариант 2: Self-Signed сертификат (для тестирования)

```bash
# Создайте самоподписанный сертификат
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/selfsigned.key \
  -out /etc/ssl/certs/selfsigned.crt

# Используйте в nginx.conf
ssl_certificate /etc/ssl/certs/selfsigned.crt;
ssl_certificate_key /etc/ssl/private/selfsigned.key;
```

## 🛡️ ЗАЩИТА ОТ ВЕБ-АТАК

### 1. XSS (Cross-Site Scripting)

**Уже реализовано:**
- CSP заголовки в nginx.conf
- X-XSS-Protection заголовок

**Дополнительно:**
```javascript
// В js/script.js добавьте функцию экранирования
function escapeHtml(unsafe) {
    return unsafe
        .replace(/&/g, "&amp;")
        .replace(/</g, "&lt;")
        .replace(/>/g, "&gt;")
        .replace(/"/g, "&quot;")
        .replace(/'/g, "&#039;");
}

// Используйте при вставке пользовательских данных
const userInput = escapeHtml(input);
```

### 2. CSRF (Cross-Site Request Forgery)

Для форм добавьте CSRF токены:

```html
<!-- В форме -->
<form id="contact-form">
    <input type="hidden" name="csrf_token" id="csrf_token">
    <!-- остальные поля -->
</form>
```

```javascript
// Генерация CSRF токена
function generateCSRFToken() {
    return Math.random().toString(36).substring(2) +
           Date.now().toString(36);
}

// При загрузке страницы
document.addEventListener('DOMContentLoaded', function() {
    const token = generateCSRFToken();
    sessionStorage.setItem('csrf_token', token);
    document.getElementById('csrf_token').value = token;
});

// При отправке формы проверяйте токен
```

### 3. Защита от SQL Injection

**Для статического сайта не применимо**, но если добавите бэкенд:
- Используйте подготовленные запросы (Prepared Statements)
- Валидируйте все входные данные
- Используйте ORM (Sequelize, TypeORM)

### 4. Clickjacking

**Уже реализовано:**
```nginx
add_header X-Frame-Options "SAMEORIGIN" always;
```

## 🌍 СЕТЕВАЯ БЕЗОПАСНОСТЬ

### 1. Firewall (UFW)

```bash
# Установка и настройка UFW
sudo apt install ufw

# Разрешаем SSH
sudo ufw allow 22/tcp

# Разрешаем HTTP и HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Включаем firewall
sudo ufw enable

# Проверка статуса
sudo ufw status
```

### 2. Fail2Ban (защита от брутфорса)

```bash
# Установка
sudo apt install fail2ban

# Создайте конфигурацию
sudo nano /etc/fail2ban/jail.local
```

Добавьте:
```ini
[nginx-http-auth]
enabled = true
port = http,https
logpath = /var/log/nginx/error.log

[nginx-noscript]
enabled = true
port = http,https
logpath = /var/log/nginx/access.log
maxretry = 6

[nginx-badbots]
enabled = true
port = http,https
logpath = /var/log/nginx/access.log
maxretry = 2
```

```bash
# Перезапуск
sudo systemctl restart fail2ban
```

### 3. Изоляция Docker сети

```yaml
# В docker-compose.yml
networks:
  itsales-network:

      config:

      com.docker.network.bridge.name: br-itsales
```
